# 006 クラウドでの運用（Fly.io）

- 状態：完了
- 依存：005

## 👤 ユーザーが確認するところ

### 何のための機能か
サーバーを Mac mini からクラウド（Fly.io の東京）に移し、Mac mini を止めても使えるようにします。

### できるようになること
- サーバーが Fly.io の東京で24時間動く。止まっても自動で再起動する
- 端末の接続先がクラウドに変わる
  - 端末のソフトの更新は、Wi-Fi 経由でできる（毎回 USB でつながなくてよい）
  - Wi-Fi 経由の更新に失敗しても、USB で書き直せる
- 確認画面も、クラウドの URL（`https://〜.fly.dev`）で開ける
- **通信はすべて暗号化する**（確認画面・端末との会話・通知）
- **データのバックアップ**：買い物リストやリマインダーのデータは、毎日自動でバックアップされる（5日分）
- サーバーにつながらないとき、端末の画面に「サーバーにつながりません」と出す（001・002 と同じ）
- Mac mini の開発用サーバーは、そのまま開発用に使える（端末をどちらにつなぐかは設定で切り替える）

### 費用の見込み
| 項目 | 月額の目安 |
|---|---|
| Fly.io（小さいサーバー1台・データ保存・端末の常時接続に必要な固定アドレス） | 数百〜1,000円程度 |
| Google Cloud と Claude（001 の見込み） | 数百円程度 |

### やらないこと
- 独自のドメイン（`〜.fly.dev` の URL を使う）
- 複数台での冗長化（家庭用のため1台）
- 監視サービスとの連携（ログと Fly.io の画面で見る）

### チャットで決めたこと
| 決めたこと | 理由 |
|---|---|
| 運用のサーバーは Fly.io の東京 | 端末との常時接続（リマインダーの通知に必要）に対応し、月数百〜1,000円程度で済む |

### 設計方針
- `fly.toml`：リージョン `nrt`、マシン1台（shared-cpu-1x、メモリは実測で決める。初期は 512MB）、`auto_stop_machines = "off"`、ボリュームは `/data`
- TLS
  - HTTPS と WSS は Fly のプロキシで終端する
  - MQTT（8883）も Fly の `tls` ハンドラで終端し、アプリには平文の TCP で渡す
  - UDP はアプリで直接受ける（音声は Xiaozhi の AES-CTR で暗号化される）
- UDP には専用の IPv4 が必要（`fly ips allocate-v4`）。料金は実装時に確認して DEPLOY.md に書く
- 秘密情報は `fly secrets import`。ユーザーが `server/.env` から実行する（Claude は値を表示しない）
- ファームウェアの OTA
  - `firmware/build.sh` で作ったバイナリを、サーバーのボリューム（`/data/firmware/`）に置く
  - OTA の応答の `firmware.version` と `firmware.url` で配る
  - 版の番号は `firmware/xiaozhi.lock` とパッチの版から作る
- 接続先の切り替え：OTA の応答で返す WebSocket・MQTT の接続先は `config.toml` の値。ファームウェアに焼く OTA の URL は、006 で Fly.io の URL に変える（1回だけ USB で書き込むか、Wi-Fi 設定のページで変える）


#### 実装中に変えたこと
- 秘密情報の登録は `scripts/fly-secrets.sh` で行う。サービスアカウントの鍵は JSON の中身を `GOOGLE_CREDENTIALS_JSON` に入れ、起動時に一時ファイルにする。
- 配るファームウェアは `/data/firmware/manifest.json` に版とファイル名を書く。manifest に書いたファイルだけを配る。

### 検討した案と不採用の理由
| 案 | 採用 | 理由 |
|---|---|---|
| Litestream で SQLite を外部のストレージに複製する | × | 家庭用にはボリュームのスナップショットで足りる。外部のストレージのアカウントが増える |
| MQTT の TLS をアプリで終端する | × | 証明書の管理が増える。Fly のプロキシに任せる |
