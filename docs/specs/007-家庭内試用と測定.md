# 007 家庭内試用と測定

- 状態：実装中
- 依存：006

## 👤 ユーザーが確認するところ

### 何のための機能か
リビングで実際に使ってみて、Alexa から置き換えられるかを判断するための材料（反応の良さ・待ち時間・誤作動・月額費用）をそろえます。

### できるようになること
- **自動で記録されるもの**
  - 会話ごとの待ち時間。工程ごとに記録する
    - 呼びかけ→聞き取り開始
    - 話し終わり→認識
    - 認識→返事の考え始め
    - →読み上げ開始
  - 1日の会話の回数
  - 聞き取った文章（確認画面の会話の記録で、聞き間違いを見られる）
  - 外部サービスの利用量
- **レポート**：コマンド1つ（と確認画面の利用量のページ）で、次をまとめて見られる
  - 待ち時間の平均と、遅かったもの
  - 1日あたりの回数
  - 今月の推定費用（Google・Claude・Fly.io の合計）
- **試用の記録用紙**：距離（2m・3m）、向き（正面・斜め）、テレビの音のあり・なし、家族それぞれの声について、反応したか・正しく聞き取れたかを記入する表を用意する
  - 間違って反応した回数（誤作動）
  - 反応しなかった回数（起動漏れ）
  - 自分の声を拾ってしまったか
- **まとめ**：試用が終わったら、Claude が記録とレポートをまとめ、次のことを書く
  - Alexa から置き換えられるか
  - 足りないところと、次に直すこと

### 使い方の流れ
1. Claude が記録用紙（`docs/TRIAL.md`）を用意する。
2. 1〜2週間、ふだんどおりに使う。気づいたことと、記録用紙の項目を書き込む（家族に声をかけて試してもらう）。
3. 「試用が終わった」と Claude に伝える。
4. Claude がレポートを出し、まとめを書く。

### やらないこと
- 待ち時間などの合格ラインを先に決めること（BRIEF のとおり、実測してから決める）
- 待ち時間を速くするための改善（まとめで次の課題として挙げ、別の仕様書にする）

### チャットで決めたこと
| 決めたこと | 理由 |
|---|---|
| 文字の会話の記録は30日残す（→ 002） | 聞き間違いの確認と、費用の記録に使う |

### ユーザーにお願いすること
- 実装前に準備するもの：なし
- 完成後に手で確認するもの
  - 記録用紙に沿った試用：距離・向き・テレビの音・家族の声。1〜2週間のふだんの利用（家庭の環境と家族の声は、Claude には再現できないため）

### 設計方針
- 集計は `server/src/report/` に置き、確認画面の利用量のページとコマンドで同じものを使う
- 記録用紙には、家族の名前ではなく「大人A」「子どもB」のような書き方を使う（公開リポジトリのため）

### 検討した案と不採用の理由
| 案 | 採用 | 理由 |

| 各社の課金 API から実際の請求額を取る | × | 権限の設定が増える。利用量×単価の推定で十分。実際の請求額は各社の画面で確かめる |
