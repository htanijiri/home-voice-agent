# 005 確認画面（Web）

- 状態：完了
- 依存：004

## 👤 ユーザーが確認するところ

### 何のための機能か
声で登録した買い物リストやリマインダーを、スマホで見たり直したりできるようにします。買い物中にリストを見たり、聞き間違いを直したりするのに使います。

### できるようになること
- スマホやパソコンのブラウザで開ける（スマホの縦向きで見やすい画面。日本語）
- **ログイン**
  - 家族の Google アカウントでログインする。あらかじめ登録したアドレスだけが入れる
  - ログインした状態は30日続く
- **買い物リスト**
  - 一覧で見られる
  - 追加・品名やメモの修正・「買った」のチェック・削除ができる
  - 「最近買ったもの」（7日分）から、リストに戻せる
- **リマインダー**
  - これから先の予定が一覧で見られる（繰り返しのものを含む）
  - 追加・日時や内容の変更・削除・次の1回だけ休む、ができる
  - お知らせできなかったものの一覧が見られる
- **端末**
  - 新しい端末の承認ができる（端末の画面に出た6桁の番号を入れる）
  - 端末の接続の状態（最後につながった時刻）が見られる
- **会話の記録**
  - 直近30日の記録（文字だけ）が見られる
  - 全部消すボタンがある
- **利用量**：今月の会話の回数と、費用の目安が見られる
- 声で変えた内容も、画面で変えた内容も、すぐにお互いに反映される

### 使い方の流れ
1. スマホで確認画面の URL を開き、「Google でログイン」を押す。
2. 買い物リストのタブで、お店で買ったものにチェックを入れる。
3. リマインダーのタブで、聞き間違いで登録された時刻を直す。

### やらないこと
- 家族ごとに見られる内容を分けること（ログインした家族は、全員同じものを見られる）
- スマホへのプッシュ通知、アプリのインストール
- Google 以外のログイン方法

### チャットで決めたこと
| 決めたこと | 理由 |
|---|---|
| 確認画面を作る | 買い物中にスマホで見られる。音声の聞き間違いを直せる |
| ログインは、登録した家族の Google アカウントだけを許可する | 合言葉1つだと、漏れたときに誰でも開けてしまう。Google の2段階認証も効く |

### ユーザーにお願いすること
- 実装前に準備するもの
  - ログインを許可する家族の Google アカウントのメールアドレス。Claude が用意する設定ファイルに自分で書き込んでください。リポジトリには入りません
  - Google Cloud で、ログイン用の設定（OAuth クライアント）を作る。手順書は Claude が用意します。006 でサーバーの URL が決まったら、その URL も登録します
- 完成後に手で確認するもの
  - 家族それぞれのスマホでログインでき、登録していない Google アカウントでは入れない（実際の家族のアカウントでのログインは、Claude にはできないため）
  - スマホでの見やすさ・使いやすさ（機械では判定できないため）

## 🤖 実装メモ（Claude 用。ユーザーは読まなくてよい）

### 受け入れ条件
- [ ] AC1：ログインしていないと、どのページと API にも入れない（ログインページを除く）（自動テスト）
- [ ] AC2：Google のログイン（OpenID Connect、認可コード＋PKCE）
  - ID トークンの署名・発行者・宛先・有効期限を検証する
  - `email_verified` が true で、許可リストのアドレスだけを通す
  - （自動テスト：偽の発行者で、許可・不許可・改ざん・期限切れを確かめる）
- [ ] AC3：セッションの Cookie
  - `HttpOnly`・`Secure`（運用時）・`SameSite=Lax` を付ける
  - 更新系の API に CSRF 対策（Origin の確認と、トークン）がある
  - （自動テスト）
- [ ] AC4：買い物リストとリマインダーの操作が、音声のツールと同じリポジトリを通って保存される（自動テスト：API のテスト）
- [ ] AC5：端末の承認が画面からできる（自動テスト）
- [ ] AC6：会話の記録の一覧と全削除ができる（自動テスト）
- [ ] AC7：スマホの幅（375px）で、横にはみ出さずに表示される（手動：Claude。内蔵ブラウザのモバイル表示でスクリーンショットを撮って確認）
- [ ] AC8：ローカル（`http://localhost`）で、Google ログインから一覧の表示まで通る（手動：Claude。ログインは Claude にはできないため、ログイン後の画面はテスト用のセッションで確かめる。実際のログインは手動：ユーザー）

### 設計方針
- 同じサーバーのプロセスで出す（Fastify）
- 画面は、サーバーで HTML を作り、少しの JavaScript を足す。ビルドの工程は持たない（家族数人が使う画面のため、フレームワークは使わない）
- OpenID Connect は `openid-client` を使う
- セッションは SQLite の `web_sessions` に保存し、Cookie にはランダムな ID だけを入れる
- 許可リストは `.env` の `WEB_ALLOWED_EMAILS`（カンマ区切り）。`.env.example` には架空のアドレスを書く
- API は `/api/shopping`、`/api/reminders`、`/api/devices`、`/api/conversations`、`/api/usage`
- 費用の目安は、`usage` の数量と `config.toml` の単価から計算する（単価は実装時に公式の料金で確かめて書く）


#### 実装中に変えたこと
- OpenID Connect は openid-client ではなく jose で実装した（ID トークンの検証の中身を明示し、偽の発行者でテストしやすくするため）。
- 本文のない更新（「買った」「削除」など）を受け付けるよう、JSON の本文が空でも通す。

### 検討した案と不採用の理由
| 案 | 採用 | 理由 |
|---|---|---|
| 合言葉1つ | × | ユーザーの指摘のとおり、漏れたときに危ない |
| パスキー | × | 登録の流れ（招待リンクなど）を作る必要があり、作るものが増える |
| Cloudflare Access などの前段の認証 | × | Fly.io の前に別のサービスを挟むことになる |
| React などのフレームワーク | × | 画面が小さく、ビルドの工程を持つほどではない |

- 自動テスト：`npm test`（認証、CSRF、API）
- 手動確認（Claude）：内蔵ブラウザでのモバイル表示
- 手動確認（ユーザー）：実際の Google アカウントでのログイン、使い心地
