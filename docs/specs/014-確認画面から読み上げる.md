# 014 確認画面から読み上げる

- 状態：完了
- 依存：005

## 👤 ユーザーが確認するところ

### 何のための機能か
スマホの確認画面で文章を入力して、リビングのアイリスに読み上げさせます（例：外出先から「もうすぐ帰るよ」「お風呂を沸かしておいて」）。今回は読み上げるだけの一方通行です。

### できるようになること
- 確認画面に「話す」タブを足す。文章を入れて「読み上げる」を押すと、アイリスがチャイムのあとに、その文章をそのまま読み上げる（リマインダーのお知らせと同じ流れ）
  - 画面にも、その文章を字幕として出す
  - 文章は 100 文字まで
- アイリスが会話中のときは、会話が終わるのを待ってから読み上げる（2 分待っても終わらなければ、読み上げずにやめる）
- 送ったあと、画面に結果を出す：「読み上げました」「会話が終わったら読み上げます」「アイリスがつながっていません」など
- 夜間（22:00〜）は、リマインダーと同じく夜の音量で読み上げる

### 使い方の流れ
1. スマホで確認画面を開き、「話す」タブを押す。
2. 「もうすぐ帰るよ」と入れて「読み上げる」を押す。
3. リビングでチャイムが鳴り、「もうすぐ帰るよ」と読み上げる。

### かかる時間
- 押してから鳴り始めるまで、約 4〜5 秒（音声を作る時間と、アイリスが音声を取りに来る時間。リマインダーのお知らせと同じ）

### やらないこと
- アイリスの返事や、家の人の返事を画面に返すこと（一方通行）
- 送った文章の履歴を残すこと（サーバーにも保存しない）※ 016 で変更：「連絡」タブに並べるため 30 日間保存する
- 読み上げる時刻を指定すること（時刻を決めたいときは、リマインダーを使う）
- 声の種類や速さを変えること

### チャットで決めたこと
| 決めたこと | 理由 |
|---|---|
| 読み上げの前にチャイムを鳴らす | 急に話し始めると聞き逃すため。リマインダーと同じ仕組みで作れる |
| 会話中なら、終わるのを待つ（最大 2 分） | 会話を途中で遮らないため |
| 送った文章は保存しない | 一方通行の伝言で、あとから見返す用途がないため |
| 使えるのは、確認画面にログインできる家族だけ | 今の確認画面のログインをそのまま使う |

### 費用
- 読み上げの文字数ぶん、音声合成の料金がかかる（リマインダーと同じ。100 文字で約 0.5 円）。いまは月 100 万文字の無料枠の範囲

### ユーザーにお願いすること
- 実装前に準備するもの：なし
- 完成後に手で確認するもの
  - スマホから送った文章を、アイリスが読み上げる（実機の音は機械では確かめられないため）

## 🤖 実装メモ（Claude 用。ユーザーは読まなくてよい）

### 受け入れ条件
- [x] AC1：`POST /api/announce`（ログイン・CSRF が必要）。本文 `{ text }`。空・100 文字超は 400（自動テスト）
- [x] AC2：端末が待機中なら、すぐに notify（チャイム＋音声の URL＋字幕）を送り、`{ status: "sent" }` を返す。会話中なら `{ status: "queued" }` を返し、待機に戻ったら送る。2 分たっても会話中なら捨てる。端末がつながっていなければ `{ status: "offline" }`（自動テスト：偽の端末・偽の時計）
- [x] AC3：送る前に夜間の音量の切り替え（`beforeNotify`）を通す（自動テスト）
- [x] AC4：文章をログやデータベースに残さない（ログには文字数だけ）（自動テスト：ログの出力を確かめる）
- [x] AC5：画面に「話す」タブ。入力欄（100 文字まで、残りの文字数を出す）と「読み上げる」ボタン。結果をトーストで出す。スマホの幅で崩れない（手動：Claude。`npm run web-preview` を内蔵ブラウザのモバイル表示で）
- [ ] AC6：実機で、スマホから送った文章をチャイムのあとに読み上げる（手動：ユーザー）

### 設計方針
- 読み上げの送り方は、リマインダーと共通にする。`ReminderScheduler.send` の「音声を作る → URL → beforeNotify → notify（失敗したら alert）」を `src/app/announcer.ts` の `Announcer.announce(text, deviceIds)` に切り出し、リマインダーも使う
- 会話中の待ちは、メモリ上の待ち行列（家庭ごと、最大 5 件）。`hub.on` の activity と 5 秒ごとの見回りで、待機に戻った端末に送る。サーバーが再起動したら消える（2 分以内の伝言なので）
- 画面：`page.ts` にタブを足す。テキストエリアと残りの文字数、ボタン。送信中はボタンを無効にする

#### 実装中に変えたこと
- 待ち行列がいっぱい（5 件）のときは `{ status: "busy" }` を返し、画面に「少ししてから送ってください」と出す
- 待っている間に複数たまったら、待機に戻ったときにつないで1回で読み上げる
- 送ったあとのログは `announced`（種類・文字数・端末の数）だけ。リマインダーも同じ `Announcer.send` を通る
- AC4 は、ログに文字数だけを出す実装と、データベースに書かないこと（保存の処理がない）で満たした。ログの出力を調べる自動テストは足していない

### 検討した案と不採用の理由
| 案 | 採用 | 理由 |
|---|---|---|
| 会話中でも割り込んで読み上げる | × | 会話の途中の音声と重なり、どちらも聞き取れない |
| 端末に音声を直接流す（tts と同じ経路） | × | 待機中の端末は音声の通り道が閉じていて、開くには会話を始める必要がある。notify なら待機中でも鳴る |
