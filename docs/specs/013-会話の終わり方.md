# 013 会話の終わり方

- 状態：実装中
- 依存：012

## 👤 ユーザーが確認するところ

### 何のための機能か
返事のあと、アイリスは「アイリス」と呼ばなくても続けて話せるように、8 秒間聞き取りを続けます。ところが、「もういいよ」「ばいばい」と言っても聞き取りを続けてしまい、その間の家族の会話を拾って「聞き取れませんでした」と言ったり、会話に返事をしてしまったりします。会話を終えたいときに、すぐ待機に戻るようにします。

### いまの動き（2026-10-25 の記録から）
- 会話を終える言葉を、ふつうの発話として返事をし、そのあと 8 秒の聞き取りを続けている
- 続けて聞き取る 8 秒の間に、まわりの声を拾うと、
  - 文字にできなかったときは「聞き取れませんでした」と言う
  - 文字にできたときは、それに返事をしてしまう（記録では、続けて聞き取る時間の終わりぎわ 5〜7 秒で拾った回が何度かあった）

### できるようになること
- **会話を終える言葉で、すぐ待機に戻る**：「もういいよ」「ばいばい」「おしまい」「ありがとう、大丈夫」など、会話を終えたいと分かる言葉には、「はい、またね。」のように短く答えて、続けての聞き取りをせずに待機に戻る
  - 言い方は決め打ちにせず、Claude が意味で判断する（「もういいよ、牛乳も入れといて」のように頼みごとが続くときは、頼みごとをしてから終える）
- **続けて聞き取る間は、「聞き取れませんでした」と言わない**：「アイリス」と呼んだあとの最初の聞き取りでは今までどおり言うが、返事のあとの続けての聞き取りで文字にできなかったときは、何も言わずに待機に戻る
- **アイリスへの話しかけでなさそうな声には答えない**：続けて聞き取る間に拾った声が、アイリスに話しかけていない（家族どうしの会話、テレビなど）と Claude が判断したときは、何も言わずに待機に戻る

### 使い方の流れ
1. 「アイリス、今日のゴミの日は？」→ 返事
2. 「ありがとう、もういいよ」→「はい、またね。」と答えて、すぐ待機（ランプが消える）。
3. そのあと家族で話していても、アイリスは反応しない。

### やらないこと
- 続けて聞き取る時間（8 秒）を変えること（設定で変えられる）
- 「アイリス」のあとの最初の聞き取りで、話しかけでない声を無視すること（呼ばれたあとは、話しかけられたものとして扱う）

### チャットで決めたこと
| 決めたこと | 理由 |
|---|---|
| 会話を終える言葉には、短く答えてから待機に戻る（黙って終えない） | 終わったことが分かるように |
| 終える言葉かどうか、話しかけかどうかは、Claude が意味で判断する | 言い方はいろいろあり、決め打ちでは取りこぼすため。操作のときと同じ仕組み（012）で、問い合わせは1回で済む |

### 設計方針
- `end_conversation` は `src/core/tools/conversation.ts`。ツールは「会話を終える」という印を `ToolContext` 経由で返す（`ctx.endConversation()`）。`Orchestrator` は終了の印を `respond` の戻り値（または最後のイベント）で `VoiceSession` に伝え、`VoiceSession.afterSpeaking` で FOLLOW_UP に入らず `finishConversation` する
- reply なしの `end_conversation` だけの回は、012 の「reply をすべて持つ」条件に当たらないが、2回目の LLM を呼ばずに終える（特別扱い）
- 続けての聞き取りかどうかは `startListening` の時点で決まる（state が SPEAKING から入ったか）。その印を `respond` に渡し、補足（systemNotes）を足す
- 無視した回（reply なしの end_conversation）は、`turns` に `outcome: "ok"`、`assistant_text` 空で残し、`error_kind` に `ignored` を入れる（会話の記録で、拾った声を見られるように）

#### 実装中に変えたこと・測った値
- 終了の印は `ToolContext.endConversation()` で `VoiceSession` に伝える（戻り値やイベントにはしなかった）
- `Tool.terminal`：reply のない end_conversation だけの回は、2回目の LLM を呼ばずに黙って終える。ほかのツールに reply があれば、end_conversation に reply がなくても、その reply で答えて終える
- 話しかけでない声として黙って終えた回は、履歴に残さず、未通知のリマインダーの案内も次の会話に残す
- 続けての聞き取りの補足の文は `FOLLOW_UP_NOTE`（どう扱うかは `prompts/system.md`）
- 評価で見つかった問題と対処
  - 「もういいよ、牛乳も入れといて」で 5回中3回、何も言わなかった。原因は2つ：(1) `maxTokens = 400` が考える分で尽き、ツールの呼び出しの途中（stop_reason が max_tokens）で切れていた。結果のない tool_use が履歴に残り、何も読み上げなかった → `maxTokens` を 800 にし、ツールの途中の max_tokens は失敗として扱う（履歴に残さない）。(2) reply を shopping_add 側にまとめ、end_conversation に reply がないと、2回目の LLM が空の返事を返していた → terminal のツールは reply がなくてよいことにした
  - そのあと 4/5（牛乳だけ追加して end_conversation を呼ばない）→ プロンプトとツールの説明に「必ず同じ回に両方呼ぶ」と書いて 10/10
  - 「ばいばい」を続けての聞き取りで、話しかけでない声として黙って終えたことが 1/5 → 「終える言葉はアイリスへの言葉として扱う」と書いて 5/5
- 結果（2026-10-25）：`eval:end` すべて合格。終える言葉の最初の文まで中央値 707ms（658〜816）。`eval:shopping`・`eval:reminder`・`eval:no-hallucination` も合格

### 検討した案と不採用の理由
| 案 | 採用 | 理由 |
|---|---|---|
| 「ばいばい」などの言葉を決め打ちで見分ける | × | 言い方がいろいろあり、「もういいよ、牛乳も」のような続きも扱えない |
| 続けて聞き取る時間を短くする | × | 続けて話せる便利さが減る。終える言葉と、話しかけでない声の無視で足りる見込み |
| 続けての聞き取りでは、声が大きいときだけ受け付ける | × | 声の大きさでは、家族の会話とアイリスへの話しかけを見分けられない |
