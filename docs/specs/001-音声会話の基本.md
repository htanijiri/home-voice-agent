# 001 音声会話の基本

- 状態：完了
- 依存：000

## 👤 ユーザーが確認するところ

### 何のための機能か
「アイリス」と呼びかけて日本語で質問すると、Claude が考えた返事がスピーカーから聞こえる。この最初の成功体験を作ります。

### できるようになること
- 「アイリス」と呼びかけるか、画面のボタンを押すと、聞き取りが始まる
- 話し終わると自動で区切り、考え始める
- 返事を自然な日本語の声で読み上げる。画面には、聞き取った言葉と返事の字幕が出る
- 返事は、スピーカーで聞きやすいように短め（2〜3文程度）にする
- 天気・ニュース・今日の予定など、まだつないでいない情報は「わからない」と答え、知っているふりをしない
- 新しい端末をサーバーにつなぐときは、初回だけ端末の画面に6桁の番号が出る。それを承認した端末だけが使える（承認は、001 では Claude が Mac のコマンドで行い、005 以降は確認画面からもできる）

### 使い方の流れ
1. 「アイリス」と呼びかける（またはボタンを押す）。
2. 端末が聞き取り状態になったら話す（例：「日本で一番高い山は？」）。
3. 話し終わると、少しして返事が読み上げられる。
4. 読み上げが終わると待機に戻る（続けて話せるようにするのは 002）。

### データの送り先
| 何を | どこへ | いつ |
|---|---|---|
| 呼びかけたあとに話した音声 | Google Cloud（音声認識） | 聞き取り中だけ。呼びかける前の音声は送らない |
| 聞き取った文章と、会話の流れ | Anthropic（Claude） | 返事を考えるとき |
| 返事の文章 | Google Cloud（音声合成） | 読み上げの音声を作るとき |

- 録音した音声はどこにも保存しません（サーバーのメモリ上で処理して捨てます）。
- Google Cloud と Anthropic の API は、初期設定では送ったデータを学習に使わないとしています（実装時に、各社の最新の規約を確認して記録します）。

### 費用の見込み
- 1日30回くらい話す場合、音声認識・音声合成・Claude を合わせて **月数百円程度**。無料枠の範囲に収まれば、さらに安くなります。サーバー代は 006 を参照してください。
- 実際の費用は 007 で測ります。

### やらないこと
- 呼びかけ直さずに続けて話すこと（→ 002）
- インターネット検索、天気、ニュース、カレンダー
- 話している途中で遮ること（→ 002）

### チャットで決めたこと
| 決めたこと | 理由 |
|---|---|
| 音声認識・音声合成は Google Cloud | 日本語の読み上げが自然。アカウントが1つで済む |
| LLM は Claude Haiku 5.5。あとから設定で変えられる | 安くて速い。品質や料金を見て変えられるようにする |
| 開発中のサーバーは Mac mini で動かす | 実機で短いサイクルで試すため。運用は 006 で Fly.io に移す |

### ユーザーにお願いすること
- 実装前に準備するもの（手順書は Claude が用意します）
  - Anthropic の API キー。Console で、月の利用上限（たとえば 10 ドル）も設定してください
  - Google Cloud
    - プロジェクトを作り、課金を有効にする
    - 音声認識（Speech-to-Text）と音声合成（Text-to-Speech）の API を有効にする
    - サーバー用の鍵（サービスアカウントの JSON）を作る
    - 予算アラート（たとえば月 1,000 円）を設定する
  - 上の API キーと鍵を、Claude が用意する設定ファイル（`server/.env`）に自分で書き込む。Claude は値を表示したり、コミットしたりしません
- 完成後に手で確認するもの
  - 返事の声が自然で聞き取りやすい（声の好みは機械では判定できないため。声の種類は設定で変えられます）

### 設計方針
- `server/`（TypeScript、Node.js の LTS、テストは vitest）
  - `src/core/`：端末と外部サービスに依存しない部分
    - `orchestrator.ts`：1回の発話の処理（STT → LLM ＋ツール → TTS）
    - `session.ts`：会話セッションと履歴
    - `ports.ts`：`SpeechToText` / `LanguageModel` / `TextToSpeech` / `Clock` のインターフェース
    - `tools/`：ツールの登録の仕組み（ツールの中身は 003・004）
  - `src/adapters/`：外部サービスの実装（`stt-google.ts`、`tts-google.ts`、`llm-anthropic.ts`）。SDK を import するのはここだけ
  - `src/transports/xiaozhi/`：Xiaozhi のプロトコル
    - `ota.ts`：OTA の口
    - `websocket.ts`：WebSocket の口
    - `opus.ts`：Opus の変換
    - `ogg.ts`：Ogg の分解と組み立て
  - `src/db/`：SQLite（better-sqlite3）とマイグレーション。テーブル：`devices`、`conversations`、`turns`、`usage`
  - `prompts/system.md`：システムプロンプト（家庭のスマートスピーカーであること、短く話すこと、知らない情報を作らないこと、今日の日時（Asia/Tokyo））
  - `config/`：`config.example.toml`（モデル名、声、上限など）。秘密は `.env`
- 音声の流れ
  - 上り：端末の Opus（16kHz、60ms）→ デコードして PCM → Google STT v2 のストリーミング認識
  - 下り：LLM の返事をストリーミングで受け、文ごとに区切って TTS に出す
    - TTS の出力（Ogg Opus か LINEAR16）は、端末に送れる Opus のフレームにする
    - 端末が 60ms 以外の長さのフレームを受けられるかは実機で確かめる。だめなら PCM を受けて 60ms で Opus にし直す
- 発話の終わりは、Google STT の発話終了のイベントを基本にする。サーバー側でも無音の判定を持ち、長すぎる発話（初期値 15 秒）は打ち切る
- 声は Chirp 3 HD の日本語の女性の声を初期値にし、`config.toml` で変えられるようにする
- 端末の認証
  - OTA の要求の `Device-Id` / `Client-Id` で端末を見分ける
  - 承認済みの端末には、ランダムなトークン（データベースにはハッシュで保存）を返す
  - WebSocket は `Authorization: Bearer` で確かめる
  - 未承認の端末には、Xiaozhi の activation の形で6桁の番号を返す
- ログは構造化 JSON。会話の本文はログに出さず、データベースの `turns` にだけ保存する（30日で削除するのは 002）


#### 実装中に変えたこと
- Claude Haiku 5.5 は thinking をオフ（effort は low）にした。履歴を古い順に切り詰める設計なので、thinking のブロックを付けて返すと、履歴を変えたときの検証でエラーになるため。応答の速さにも有利。
- 現在の日時はシステムプロンプトではなく、毎回の発話に添える。システムプロンプトとツールを固定して、プロンプトのキャッシュを効かせるため。
- 端末の承認は Device-Id（MAC）と Client-Id（端末の中の UUID）の組で行う。Client-Id が変わったら承認し直す（MAC は無線で見えるため、MAC だけでトークンを出さない）。
- Claude が安全のために回答を断った場合（stop_reason が refusal）は、「その質問にはお答えできません」と答え、履歴には残さない。

### 検討した案と不採用の理由
| 案 | 採用 | 理由 |
|---|---|---|
| 最初から MQTT＋UDP で作る | × | 調査がしにくい。まず WebSocket で会話を成り立たせ、通知が必要になる 004 で MQTT＋UDP を足す |
| サーバー側で音声区間検出（Silero など）を入れる | × | まずは Google STT の発話終了イベントで足りるかを見る。足りなければ足す |
| Python（xiaozhi-esp32-server を流用） | × | 中国のサービスとの連携や多機能な部分が多く、必要な部分だけを TypeScript で作るほうが見通しがよい |
