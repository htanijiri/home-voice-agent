# 000 開発環境と実機確認

- 状態：完了
- 依存：—

## 👤 ユーザーが確認するところ

### 何のための機能か
端末に自分たちでビルドしたソフトを書き込み、マイク・スピーカー・画面・ボタン・Wi-Fi が動くことを確かめます。以降のすべての土台になります。

### できるようになること
- Mac で端末用のソフト（Xiaozhi）をビルドして、USB で書き込める
- 端末が家の Wi-Fi につながる。電源を入れ直しても、自動でつなぎ直して待機状態に戻る
- 録音して再生するテストで、マイクとスピーカーが動くことを確かめられる
- 画面に日本語が出る
- 書き込みに失敗しても、USB でいつでも書き直せる（元に戻す手順を残す）
- 確認した結果（何が動き、何が動かなかったか）を記録に残す

### 使い方の流れ
1. AtomS3R を Echo Pyramid に取り付ける。Pyramid 底面の USB-C に電源（USB 充電器か Mac）を、AtomS3R 側の USB-C に Mac をつなぐ。AtomS3R 側の線は、書き込みと動作ログの確認に使う。
2. Claude が Mac に開発ツールを入れ、ソフトをビルドして書き込む。
3. 端末が「Wi-Fi 設定モード」になるので、スマホで端末の Wi-Fi に接続し、表示されたページで家の Wi-Fi を選んでパスワードを入れる（Wi-Fi のパスワードは端末の中にだけ保存され、Claude もリポジトリも扱わない）。
4. 録音・再生のテストをして、声がはっきり聞こえるかを確かめる。
5. ふだんは Voice Pyramid 側の USB-C から給電してリビングに置く。

### やらないこと
- Claude との会話（→ 001）
- xiaozhi.me（Xiaozhi の公式サービス）への登録・接続
- 9軸センサーなど、使わない部品の確認

### チャットで決めたこと
| 決めたこと | 理由 |
|---|---|
| 端末のソフトは M5Stack 公式の Xiaozhi を使い、バージョンを固定する（v2.5.2） | 一から作らず、公式に対応済みのものを使う。固定することで、あとで同じものを作り直せる |
| xiaozhi.me には接続しない。接続先は自作サーバーだけ | 音声の送り先を自分で管理する |
| ウェイクワードは「アイリス」 | 日本語で呼びやすい |
| 「アイリス」のために、端末ソフトが使う音声認識の部品を新しい版に上げる。うまく動かなければ「Hi Stack Chan」にする | 「アイリス」は新しい版にしか入っていないため |
| リポジトリは GitHub で公開する。ライセンスは MIT（Claude の提案） | 記事にするときにリンクできる。MIT は利用する Xiaozhi と同じ |

### ユーザーにお願いすること
- 実装前に準備するもの
  - 端末と Mac をつなぐ USB-C ケーブル
  - Mac に開発ツール（ESP-IDF、数GB）を入れてよいかの了承（インストール作業は Claude が行う）
- 実装中にお願いすること
  - 書き込みのあと1回だけ、スマホで端末の Wi-Fi 設定をする（そのときに声をかけます）
- 完成後に手で確認するもの
  - 録音・再生のテストで、自分の声がはっきり聞こえる（音の聞こえ方は機械では判定できないため）

### 設計方針
- `firmware/`
  - `xiaozhi.lock`：取得するリポジトリ、タグ、コミットハッシュ
  - `sdkconfig.defaults.local`：言語、ウェイクワード、OTA URL（例の値）を重ねる。実際の OTA URL は gitignore した `firmware/config.env` から差し込み、`firmware/config.env.example` を置く
  - `patches/`：元ソースへの小さな変更（esp-sr の版上げ、002 で使うボタン長押しなど）。`git apply` で当てる
  - `build.sh` / `flash.sh`：取得 → パッチ → ビルド → 書き込み。取得したソースは `firmware/.build/`（gitignore）に置く
- ESP-IDF は、xiaozhi v2.5.2 が要求するバージョンを README と CI 設定から確認して入れる（`~/esp/` 配下に置く。brew では入れない）
- esp-sr を 2.5.5 以上に上げて、ビルドエラーが出たら最小限のパッチで直す。直せない場合は `wn9_histackchan_tts3`（Hi Stack Chan）に切り替え、TASKS.md の決定事項ログに書く（チャットで決めた代わりの候補なので、確認は不要）
- 000 の時点の OTA URL は、Mac mini の LAN 内アドレスに向ける。001 で本物の OTA の口を作るまでは、ログを出すだけの仮サーバー（`server/tools/ota-stub.ts`）で受ける
- 録音・再生のテストは、Xiaozhi の Wi-Fi 設定モードにある音声テスト（`kDeviceStateAudioTesting`）を使う


#### 実装中に変えたこと
- 書き込みは `idf.py flash` ではなく、ビルドで作られる1つにまとめたバイナリ（merged-binary.bin）を esptool で書き込む（`idf.py` が再ビルドを始め、Python の環境の違いで止まったため）。
- xiaozhi の `scripts/build.py` はウェイクワードのモデル名を wn9 系しか受け付けないため、wn10 を許すパッチ（`patches/0001-build-wakenet10-names.patch`）を足した。esp-sr は 2.6.0 でビルドが通った。
- `CONFIG_SEND_WAKE_WORD_DATA=n` にした。呼びかけた声（ウェイクワードの部分）をサーバーへ送らず、端末が聞き取り開始の音を鳴らす。
- 版は `2.5.2.<自作ビルドの番号>`（`xiaozhi.lock` の `HVA_BUILD`）にする。006 の Wi-Fi 経由の更新で、新しい版と判断させるため。

### 検討した案と不採用の理由
| 案 | 採用 | 理由 |
|---|---|---|
| M5Burner で配布されている Xiaozhi を書き込む | × | 接続先が xiaozhi.me になり、アカウント登録が必要 |
| 自分でビルドした Xiaozhi を書き込む | ○ | 接続先・言語・ウェイクワードを設定できる |
| xiaozhi-esp32 をフォークして直接変更する | × | 公式の更新を取り込みにくい。パッチを重ねる形にする |

### 検証方法
- コマンド：`firmware/build.sh`、`firmware/flash.sh`、`strings` と grep による秘密情報の検査
- 手動確認（Claude）：シリアルログ。ウェイクワードは Mac のスピーカーから再生した音声で確かめる
- 手動確認（ユーザー）：録音・再生の音質（機械で判定できないため）
