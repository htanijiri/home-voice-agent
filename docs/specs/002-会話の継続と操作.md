# 002 会話の継続・状態表示・操作・エラー復帰

- 状態：完了
- 依存：001

## 👤 ユーザーが確認するところ

### 何のための機能か
毎回「アイリス」と言わずに続けて話せるようにし、日常で使える使い勝手（状態の表示、マイクオフ、音量、失敗したときの案内）を整えます。

### できるようになること
- **続けて話せる**
  - 返事の読み上げが終わると、そのまま 8 秒間は聞き取りを続ける。呼びかけ直さずに次の質問ができる
  - 何も話さなければ待機に戻る（秒数は設定で変えられます）
- **前の話を覚えている**
  - 「それはどうして？」のような追加の質問が通じる
  - 待機に戻ってから 5 分以内に話しかけた場合も、前の話の続きとして扱う。5 分を過ぎると前の話は忘れる（時間は設定で変えられます）
- **途中で止められる**：読み上げの途中で「アイリス」と言うかボタンを押すと、読み上げを止めて聞き取りに移る
- **ボタン（AtomS3R の画面）**
  - 押す：会話を始める／終える
  - 長押し（2秒）：マイクをオフにする／オンに戻す
  - マイクオフの間は、呼びかけにも反応しない。画面に「マイクオフ」と出し、LED を赤にする
  - マイクオフは、電源を入れ直しても続く
- **状態の表示**
  - 待機・聞き取り中・考え中・話し中・エラー・マイクオフを、画面と LED で見分けられる
  - 考え中は、画面に考え中の表情を出す
- **失敗したときの案内**（待機に戻るまでの動き）
  - 聞き取れなかったとき：「すみません、聞き取れませんでした」と言って待機に戻る
  - Claude や Google の調子が悪いとき・15 秒たっても返事ができないとき：「ただいま調子が悪いようです。少ししてからもう一度話しかけてください」と言って待機に戻る
  - 読み上げ自体が作れないときは、画面に案内を出す
  - Wi-Fi やサーバーにつながらないとき：画面にエラーを出し、自動でつなぎ直す。つながったら待機に戻る。何度も繰り返して固まったり、無反応になったりしない
- **音量**
  - 「音量を上げて」「下げて」「音量を5にして」で変えられる
  - 夜間（22:00〜7:00）は、返事と通知を小さめの音量にする
  - 夜間に声で音量を変えた場合は、朝7時に昼の音量へ戻る
- **使いすぎの防止**
  - 1日の会話の回数に上限を設ける（初期値 200 回）。上限を超えると「今日の利用上限に達しました」と答えて、Claude と Google を呼ばない
  - 返事の長さと、覚えておく会話の長さにも上限を設ける
- **会話の記録**：文字にした会話の記録を30日残し、それより古いものは自動で削除する

### 使い方の流れ
1. 「アイリス、富士山の高さは？」→ 返事を聞く。
2. 呼びかけずに「それって世界で何番目？」→ 前の話を踏まえて答える。
3. 8 秒黙ると待機に戻る。
4. 夜、テレビの音で反応してほしくないときは、ボタンを長押ししてマイクをオフにする。

### やらないこと
- 自分の読み上げの声をマイクが拾って、自分に返事をしてしまう問題の完全な対策。端末のエコー対策で足りるかを実測し、足りなければ聞き取りを始めるまでの間を空けるなどで対処する
- 話している最中に、呼びかけなしで割り込む会話（完全な同時双方向会話）
- 家族ごとに話し方を変えること

### チャットで決めたこと
| 決めたこと | 理由 |
|---|---|
| 文字の会話記録は30日残して自動で削除する。録音した音声は保存しない | 不具合の調査と費用の記録に使う。音声は残さない |
| 夜間（22:00〜7:00）は自動で音量を小さくする。時間と音量は設定で変えられる | 夜間の生活音への配慮 |

### ユーザーにお願いすること
- 実装前に準備するもの：なし
- 完成後に手で確認するもの
  - 続けて話すときの待ち時間（8 秒）と、前の話を忘れるまでの時間（5 分）が、ちょうどよいか（使い心地は機械では判定できないため。設定で変えられます）
  - LED の色と画面の表示で、状態が見分けられるか（見やすさは機械では判定できないため）
  - ボタンの長押しでマイクがオフになり、呼びかけても反応しない。もう一度長押しすると戻る（ボタンを押す操作は Claude にはできないため）

- [ ] AC6：声での音量の変更（端末の MCP ツール `self.audio_speaker.set_volume` を呼ぶ）と、夜間の音量の切り替え・朝の戻しができる（自動テスト：偽の時計と偽の端末。実機では手動：Claude）
- [ ] AC7：1日の上限を超えると、外部 API を呼ばずに上限の案内を返す（自動テスト）

### 設計方針
- 連続会話は、Xiaozhi の自動モード（`listen` の `mode: "auto"`）を使う。`tts stop` のあと端末が聞き取りに戻り、サーバーは `followUpSeconds`（初期値 8）の間に発話がなければ聞き取りを終える
- 文脈の保持
  - セッションの履歴は、端末ごとにメモリと `turns` テーブルに持つ
  - `contextKeepMinutes`（初期値 5）以内の再開なら、同じ履歴を使う
  - 履歴は直近 `maxHistoryTurns`（初期値 10）往復まで
- 「考え中」：`stt` を送ったあとに `llm` の emotion を `thinking` で送る
- マイクオフはファームウェアのパッチで作る（`firmware/patches/`）
  - ボタンの長押しで、ウェイクワードの検出と聞き取りを止める
  - 状態は NVS に保存して、再起動しても続くようにする
  - 画面には「マイクオフ」と出し、LED は赤にする
  - サーバーは関与しない
- 音量
  - 声での変更は、LLM のツール `set_volume` から端末の MCP の `tools/call` に変える
  - 夜間の切り替えは、セッションの開始時と通知の前に、時刻を見て音量を送る（常時接続ができる 004 以降は、22:00 と 7:00 にも送る）
- 利用上限：`usage` テーブルで、日ごと（Asia/Tokyo）の会話の回数とトークン数・音声の秒数・文字数を数える
- 30日の削除：起動時と毎日 4:00 に `turns` を削除する


#### 実装中に変えたこと
- LED の色：待機は青、聞き取り中は緑、話し中は水色、マイクオフは赤。元のファームウェアでは話し中が赤だったので、マイクオフと見分けるために水色に変えた。
- マイクオフ中にボタンを押しても会話は始めず、画面に「マイクオフ」と出す。
- 夜間に入るときに、その時点の音量を覚えておき、朝7時にその音量へ戻す（初期値の昼の音量ではなく、直前に使っていた音量）。
- 端末の音量 0〜100 は -50〜0dB に等間隔で割り当てられる（esp_codec_dev の既定）ので、50 未満はほとんど聞こえない。声で使う段階 0〜10 は「0＝消音、1〜10＝37〜100（7 ずつ）」に割り当てる。昼の初期値は 65、夜間は 50 にした（最初の 70・40 と、段階×10 の割り当てでは、夜間と小さい段階が聞こえなかった）。
- 運用のコマンド `src/cli/set-volume.ts` で、サーバーから端末の音量を指定できる（つながっていれば1分以内に反映）。
- 読み上げの最後の音声を送ってから、「読み上げ終了」を送るまでに最低 100ms 空ける。UDP の音声が MQTT の終了より後に届くと、端末に捨てられるため。

### 検討した案と不採用の理由
| 案 | 採用 | 理由 |
|---|---|---|
| マイクオフをサーバー側で持つ（サーバーが接続を断る） | × | 端末はウェイクワードを聞き続けてしまう。マイクオフは端末で止めるのが正しい |
| 文脈を LLM で要約して長く持つ | × | 長期記憶は今回の範囲外。直近の往復だけを持つ |
