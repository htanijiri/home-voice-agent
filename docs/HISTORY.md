# home-voice-agent ― 開発の記録

## 1. このアプリは何か
M5Stack の AtomS3R（コントローラー）と Voice Pyramid（マイク・スピーカー・LED 付きの台座）を、クラウドの LLM と日本語で話せる家庭用スマートスピーカーにする。
リビングで使っている Alexa の主な用途（買い物リスト・リマインダー）を置き換え、そのうえで会話や外部連携を自由に広げられることを価値にする。

### 出発点となった要望（2026-10-20）
- 自宅リビングの Alexa は、ほぼ「買い物リスト」と「リマインダー」にしか使っていない。そこで、家族が自然な日本語で使える自作スマートスピーカーで置き換えたい。
- ハードウェアは購入済み（AtomS3R＋Voice Pyramid、合計で約8千円）。リビングに置いて常時給電する。2〜3m離れたところから、テレビなどの生活音がある中で呼びかけたい。
- 優先順位
  1. 音声会話が成り立つこと（ウェイクワード→日本語で質問→クラウドLLMの返事を音声で再生、続けて話せる）
  2. 買い物リストとリマインダー
  3. それ以外（独自のウェイクワード、カレンダー、センサー、長期記憶など）はあとで
- LLM はクラウドの API（Claude Haiku 系が第一候補）を使い、あとからモデルを変えられるようにする。
- ハードウェアに依存する処理と、会話・ツール実行・データ管理を分ける。将来、別の端末（スタックチャンなど。家族の話し相手になる卓上ロボットの構想がある）から同じ仕組みを使えるようにしたい。
- 実運用は、自宅の Mac mini の常時稼働に頼らないクラウド構成を目標にする。
- API キーは端末に入れない。ウェイクワードは端末の中で判定し、ふだんの音声をクラウドに送らない。録音した音声は原則保存しない。
- 費用は、音声認識・音声合成・LLM・サーバーを合わせた月額を記録し、想定外の従量課金を防ぐ仕組みを入れる。

## 2. 主要な設計判断と、その理由

### 端末は Xiaozhi 公式ファームウェア＋自作サーバー（ESPHome＋Home Assistant にしない）
- M5Stack の公式手順には、「ESPHome＋Home Assistant」と「Xiaozhi」の2つがある。
- ESPHome＋Home Assistant は最短で動くが、Home Assistant を家で24時間動かす必要があり、「家の Mac mini に頼らない」という目標に合わない。ウェイクワードの標準モデルも英語だけ。
- Xiaozhi（MIT ライセンス、この機種に正式対応）は、接続先を自作サーバーに変えられる。
  - 端末が直接クラウドへつながる。
  - 次の機能が最初から入っている：
    - 端末内のウェイクワード
    - 続けて話せる会話
    - サーバーからの通知の再生
    - 日本語の画面表示
  - 将来のスタックチャンにも Xiaozhi 対応版があり、同じサーバーを使い回せる。
- 公式の xiaozhi.me サービスには接続しない（音声の送り先を自分で管理するため）。

### ウェイクワードは日本語の標準モデル「アイリス」
- Espressif（チップのメーカー）の音声認識ライブラリに、日本語の標準モデル「アイリス」がある。4文字の名前で子どもも呼びやすい。
- 固定する Xiaozhi のバージョンが使っているライブラリは古く、このモデルが入っていない。そのため、ライブラリを新しい版に上げてビルドする。動かなかった場合は英語の標準モデル「Hi Stack Chan」にする。

### 音声認識・音声合成は Google Cloud
- 日本語の読み上げが自然で、無料枠がある。1つのアカウントで両方をまかなえ、確認画面の Google ログインも同じところで設定できる。

### サーバーは Fly.io（東京）
- リマインダーを時刻どおりに鳴らすには、端末とサーバーが常時つながっている必要がある。Xiaozhi はこの常時接続に MQTT と UDP を使う。
- Cloudflare Workers は安いが、この通信方式に対応しないため選ばなかった。国内の VPS は OS の管理が必要になるため選ばなかった。

### 確認画面のログインは Google アカウント
- 合言葉1つの方式は、漏れたときに誰でも開けてしまうのでやめた。
- 登録した家族の Google アカウントだけが入れるようにする。パスワードの管理が要らず、Google の2段階認証も効く。

### リポジトリは GitHub で公開する
- 家族の情報・メールアドレス・Wi-Fi の名前・実際の会話は書かない。秘密情報は `*.example` だけを置く。

## 3. 開発の時系列
### 第1期：設計とMVP（2026-10-20 〜）
- 2026-10-20：BRIEF をもとにキックオフ。方式の比較を調べ、未決事項をチャットで決めて、仕様書 000〜007 を作成。
- 2026-10-21：クラウド（Fly.io）に移し、家庭内試用を始めた。試用の初日に見つかった2点を直した。
  - 返事の先頭の1〜2文字が欠ける：端末が「話し中」に切り替わるときに受信済みの音声を捨てていた。サーバーが最初の音声を送るのを少し待つようにした
  - 声で追加した買い物リストが、開いている確認画面に出ない：サーバーから変更を知らせる仕組み（SSE）を足した（仕様書 008）
- 2026-10-23：リビングでの試用の指摘から、リマインダーは登録した言葉だけを読み上げるようにした（仕様書 010）。離れた場所から聞き取れない件は、録音の音量を下げても認識できたので、まず聞き取りごとの数字を記録して原因を調べることにした（仕様書 009）。
- 2026-10-23：009 の記録から、離れた場所で聞き取れない原因は、Google の話し始めの合図の遅れと、待ち時間切れで声を捨てていたことだと分かった。サーバーでも話し始めを判定し、声を捨てないようにした（仕様書 011）。
- 2026-10-24：返事の速さに取り組んだ（仕様書 012）。音声合成をストリーミングにし、操作のときは Claude が先に決めた言葉で答えて問い合わせを1回にした。評価では、買い物リストへの追加の返事が約 0.6 秒速くなった。
